Принятые именования (не изобретай новых без причины):
* файл — `script-ch<N>_1.rpy`, `script-ch<N>_2.rpy`, … (пролог — `script-ch0.rpy`)

  `si_room_ch1_3`, `hallway_ch1_8`, `library_ch1_8`

* `call overlay_screen(...) from _call_overlay_screen_K` — `K` уникален во всём проекте

**Резка главы на части** — стандарт зафиксировать явно (сейчас он не записан нигде, кроме
примера главы 1: 10 частей / 1244 реплики / 1154 голосовых ≈ 115 голосовых на часть,
рез по смене локации и по `→ next scene`). Решение за тобой: твоя инструкция должна
дать агенту перевода **детерминированный** алгоритм, чтобы имена частей не расходились.

## 4. Открытые проблемы, которые должен закрыть агент структуры

### 4.1 🔴 Справочник `image id → имя ассета` (главный)

Факты, уже установленные:
* `(0x02000000 +K)` — **единый** id-пространствo для фонов, CG и спрайтов:
  `stage` → 117 id в диапазоне 1..1173; `event` → 197 id в 1..1176;
  `layN` → 322 id в **302..1125**; пересечений «спрайты↔фоны/CG» = **0**.
  Всего используется 634 разных id из диапазона 1..1176.
* id **не совпадает** с номером записи в PNG-распаковке:
  `SCENEDAT.BIN` содержит записи 0,1,2,3,4,16,17,… (нет 5..15), а фоновые id включают 10..15;
  `NORMAL.BIN` содержит 0,7,17,… (нет 1..6), а фоновые id включают 1..6.
* значит, где-то есть **транслирующая таблица**. Кандидаты:
  `NORMAL.HD` (1440 Б), `SCENEDAT.HD` (4736 Б), `SLPS_257.09`, или таблица,
  которую движок строит функциями `loadImage()` / `loadChangeImage()` из `output/scripts/SCENE_000x.txt`
  (сцены 0–3 — библиотека движка, там же `sceneMain`, `Layer`, `ScreenLayer`).

Требуемый результат: файл-справочник вида
```
image_id,kind,name           # kind ∈ {bg, cg, chara, ui, unknown}
28,bg,forest
390,chara,l 1
148,cg,l_s_forest
```
**Bootstrap, если таблицу не удастся вывести аналитически:**
1) сопоставить уже портированные главы 0–1 (по ним известно ~200 пар
   «сцена → использованное имя», см. `output/_diagnostics/crosswalk.txt`);
2) остальное — визуально: `unpacked/SCENEDAT.BIN/*.PNG` (1104) и `unpacked/NORMAL.BIN/*.PNG`
   против `game/images/{bg,cg,chara}` (65/41/289);
3) каждую найденную пару **сразу записывать** в справочник, чтобы порт главы 2+ был
   механическим. Имя файла справочника и место хранения — твоё решение, объяви его
   в `TRANSLATION_AGENT.md` §7.

## 6. Требования к предоставленным скиллам (что доработать)

Заявленные скиллы нужно привести так, чтобы **каждый из пунктов ниже был закрыт
одним однозначным указанием**. Если скилла нет или он этого не покрывает — допиши.

1. **Парсер источника.** Разбор `chapters/*.txt` (многострочные реплики, `：`,
   `[voice N]`, скобочные события) и `events_full/*.txt` (сырые `set/talk/next/
   selectItem/dateItem`). Должен **игнорировать** многострочность и CP932-подвохи
   (`、` = `0x81 0x5C`), учитывать две сигнатуры `talk()`.
2. **Порядок обхода.** Как идти по главе: границы главы, разбивка на части, порядок
   «событие → реплика → выбор → переход», что делать с `extra scenes:`.
3. **Таблица PS2→Ren'Py** (у агента перевода она в §4) — скилл должен отдавать её
   машиночитаемо, а не только текстом.
4. **Голоса.** id → `VOICE_ID.BIN_%08X.wav` → `STV` → `ogg` → `ch<N>[.<M>]_<spk>_<NNN>`;
   где брать расшифровку; правило «идти по id, а не по тексту»; правило удаления/пометки
   строки в CSV.
5. **Переводы.** EN-база в сценарии + `old/new` в `tl/japanese` и `tl/russian`;
   бакеты; требование дословного совпадения `old`; правила из `PROMTS.md`.
6. **Ren'Py API ремастера.** Сигнатуры `scene_fx/fade_fx/dissolve_fx/flash_fx/hit_fx/
   blow_fx/shake_fx`, `show_sprites`, `update_sympathy`, `overlay_screen`,
   `portrait_choice/sprite_choice`; уникальность `from _call_overlay_screen_K`;
   как `dir`/`level` PS2 **не** переносятся буквально.
7. **Ассеты.** Правило BGM `t{K-1}`; что делать с SE; путь к справочнику
   `image id → имя` (§4.1); где лежат оригиналы PNG/STV.
8. **Проверка качества.** Автопроверки: уникальность `label`, существование `.ogg`,
   полнота `tl` для новых EN-строк, отсутствие английского в JA/RU-режиме,
   счётчик реплик против `chapter_map.txt`, запуск/компиляция проекта.
9. **Ограничения.** Японский — канон; главы 0 и 1 — неприкосновенный эталон;
   git vs медиа-папки; «не редактировать существующее без нужды».

## 7. Ограничения

* **Не портируй диалоги и не переводи** — это агент `TRANSLATION_AGENT.md`.
* **Не ломай главы 0 и 1** — они эталон, от которого зависит вся механика.
* Изначальный канон текста — **японский**; EN — базовый язык ремастера; RU — перевод.
* Существующие файлы не переписывай архитектурно; добавляй недостающее.
  Исключение — явная гигиена (§4.5), и то сначала согласуй.

  и читай инструментом `read`. `python -c "…"` с кавычками ломается — создавай `.py`.
* Правило «git vs медиа» — см. `game/INSTRUCTION.md`; новые медиа не коммить в git.
