# project-constraints — ограничения, действующие всегда

Скилл самодостаточен: его правил достаточно, чтобы не нарушить проект. Общие
процедуры (резка глав, workflow, отчёты) — в `AGENTS.md` и профильных скиллах;
при противоречии **приоритет у `AGENTS.md`**, но и без него пункты ниже обязательны.

## 1. Языки: JA — канон

```text
JA = истина смысла        ps2_source/chapters/*.txt
EN = база ремастера       пишем мы, лежит в game/chapters/**/script-*.rpy
RU = перевод              пишем мы, лежит в game/tl/russian/**
```

* **JA > EN** и **JA > RU** при любом конфликте.
* Ни EN, ни RU никогда не доказательство исходного смысла — в том числе текст,
  написанный этой же сессией.
* Расхождение EN ↔ RU не решается молча: обе формы проходят по JA → флаг
  `RECONCILE` в `reports/log.md`; по JA одна неверна → правится эта форма.
* **Модальность неприкосновенна**: вопрос, сомнение, предположение, возможность,
  необходимость, категоричность, степень эмоции не усиливаются и не ослабляются
  ради «естественности».
* **Не выдумывай JA-доказательство.** «В JA сказано X» требует реального X в
  доступном JA-контексте. Нет опоры → формулировка «JA прямо этого не подтверждает»,
  пометка `???`, запись в журнал.
* Обратный перевод — **диагностический инструмент**, не арбитр над JA: ловит смену
  субъекта/числа/роли и смысловой сдвиг, но по нему нельзя «исправлять» корректный текст.

## 2. Эталоны и «не переписывать без нужды»

* `game/chapters/0/` и `game/chapters/1/` — **эталон механики**: цепочка `jump`,
  имена `voice`, `*_fx`, `menu`/`*_choice`, `overlay_screen`, симпатия, бакеты `tl`.
  Архитектурно они **не переписываются**. Текстовые правки допустимы (ошибка
  перевода — тоже ошибка), но только с записью в `reports/log.md` и прогоном
  `tools/check_project.py`.
* **Существующее не переписывается без нужды.** Работа — добавлением: новые главы и
  строки, новые вызовы, новые записи справочников. Архитектурная правка работающего
  кода — только если без неё нельзя продолжить, и с записью в журнал.
* **Предпочтение редактора ≠ доказательство ошибки.** Грамматически корректная
  формулировка, сохраняющая смысл по JA и соблюдающая правила оформления, остаётся.
  Leave-Unchanged Accuracy важнее количества правок; **ноль правок — допустимый итог**.
* Словари (`dictionary.md`, `addresses.md`) — тоже не переписываются: правки идут
  **добавлением** и через журнал; каноническая форма не меняется задним числом.

## 3. Жизненный цикл сигнала (обязателен)

Любой сигнал — сканер, скилл, подозрение, ручная находка — проходит:

```text
DETECT → INVESTIGATE → COMPARE → CLASSIFY → DECIDE → EDIT → RECHECK → RECORD
```

* **Ни один scanner, pattern, regex или heuristic не разрешает правку сам по себе**:
  обнаружение означает только «здесь требуется проверка», а не «это ошибка».
* **Classification** (характеристика места): `ERROR` / `WARNING` / `CANDIDATE` / `PASS`.
* **Disposition** (судьба кандидата): `FIXED` / `FALSE POSITIVE` /
  `PRESERVED — FUNCTIONAL` / `PRESERVED — JA` / `PRESERVED — CHARACTER VOICE` /
  `ACCEPTABLE ADAPTATION` / `USER DECISION` / `???`.
* Кандидат, дошедший до решения, обязан получить **оба** значения. Формат
  «находка → исправлено» без classification/investigation/disposition **запрещён**;
  объединение нескольких кандидатов — только с явным перечислением всех.
* Отчёт различает **detection ≠ classification ≠ investigation ≠ disposition**.
* **Все отклонения от источника фиксируются** в `reports/log.md` (удаления,
  сокращения, расхождения JA ↔ EN ↔ RU, сомнения). Молча ничего не удаляется.
* Места, требующие решения человека, — пометка `???` в отчёте части + запись в журнал.

## 4. UNCERTAINTY ≠ STOP

Неопределённость классифицируется по масштабу, а не останавливает работу.

| масштаб | пример | действие |
|---|---|---|
| 🟢 **локальный** (один термин, фраза, название) | как переводить имя локации | исследовать JA → `dictionary.md`/`addresses.md` → контекст → этимологию; выбрать обоснованную форму; пометить `PROVISIONAL`; записать в журнал; **продолжить** |
| 🟡 **средний** (влияет на несколько последующих мест) | новый неписаный термин главы | временное решение + `PROVISIONAL` + перечень мест использования (traceability) + продолжение |
| 🔴 **блокирующая** (без решения нельзя корректно продолжить / риск массового распространения / меняется утверждённый канон) | противоречие канона | блокировать **минимальный участок**, не всю главу |

* **PROVISIONAL ≠ CANONICAL**: неподтверждённая форма не пишется в `dictionary.md`
  как канон (только с явной пометкой `PROVISIONAL`). Путь:
  `PROVISIONAL → USER CONFIRMED → CANONICAL` либо
  `PROVISIONAL → REJECTED → заменить все места использования`.
  Каждый новый PROVISIONAL-термин указывается в отчёте части.
* **PROVISIONAL ≠ WAIT**: подтверждения не ждут. Отложенные вопросы — статус
  `OPEN`/`DEFERRED` в `reports/log.md`, считаются **не решёнными** и разбираются
  отдельным проходом после главы.
* Блокирующие вопросы не задаются «начинать ли?»: получив задание, агент проходит
  `ANALYSIS → CLASSIFICATION → PROVISIONAL RESOLUTION → EXECUTION` и начинает первую
  часть; спрашивать разрешение начать или возвращать только план — запрещено.

## 5. Кодировка и канал передачи текста

* **PowerShell здесь cp1251**: японский/русский в консоль **не печатать**
  (получится `????`/мусор); даже `Get-Content -Encoding UTF8` отдаёт кракозябру.
  Код консоли проверяется ASCII-выводом (`tools/check_project.py` печатает только ASCII).
* **Кириллица/японский не передаются в аргументы командной строки и через конвейеры
  shell** — канал искажает символы. Порядок: написать текст в UTF-8-файл инструментом
  записи → команде передавать только **путь** → после записи прочитать файл и
  убедиться, что нет подмены букв и `?` вместо символов.
* `python -c "…"` с кавычками/переносами ломается — создавать `.py`-файл и запускать.
* Все выходные файлы — UTF-8 **явно** (`encoding="utf-8"`); `errors="replace"`
  допустим только для чернового анализа.
* Чтение файлов — инструментом чтения, а не консолью.

## 6. Git

* **`git commit` — только после явного подтверждения пользователя на конкретный набор
  изменений.** Ни один скилл, скрипт, подагент или механизм не могут отменить это
  правило. Успешные проверки, «сохранить прогресс» и общее разрешение редактировать
  файлы — **не** разрешение на коммит.
* Предложить коммит можно: назвать сообщение и перечень изменений. Без подтверждения
  изменения остаются незакоммиченными.
* `git status`, `git diff`, `git log`, `git show`, сравнение ревизий — разрешены.
* **git vs медиа** (`game/INSTRUCTION.md`): в git — скрипты (`.rpy`, `tl/`,
  `references/`, `reports/`, `tools/`, `ps2_source/`, `dictionary.md`, `addresses.md`,
  `transcriptions_ja_ru.csv`); **не коммитятся** «динамические» папки `audio`, `gui`,
  `images`, `video` и все `*.ogg/*.png/*.webp/*.wav/*.webm`. Медиа живут архивом
  в облаке; полное обновление = `git pull` + скачать архив и положить в `game/`
  (старые папки предварительно удалить).

## 7. Запрет промежуточных артефактов

* **Единица записи — файлы проекта** (`*.rpy`, `tl/*`, `reports/*`): писать их
  инструментом записи и проверять прочтением.
* Промежуточных `output/`, `translates/`, `merged/`, `completed.md`, `output/_log/`,
  `output/_audit/` в проекте **нет** — не создавать их по привычке.
* Устаревшие инструкции (`TRANSLATION_AGENT.md`, `STRUCTURE_AGENT.md`,
  `NOVELL_AGENTS_INSTRUCTION.md`) **удалены**: их содержание живёт в
  `AGENTS.md` и скиллах `.agents/skills/` — других источников нет.
* Остатки прошлого в `tl/` (`*.bak`, `*.rpyc.bak`, `dot_checker.py`) удаляются
  **только по согласованию с пользователем**; агенты их не создают и не используют.
* `ZNT_TEST/output` перенесён в `ps2_source/` — двойных копий источника не держать.

## 8. Медиа и ресурсы — кратко

* Новые голоса/картинки/BGM **не коммитятся** (см. §6); `.ogg` — в `game/audio/voices/`
  локально и в облачном архиве.
* Имена BGM — только `t{K-1}`, картинки — через `references/image_id_map.csv`
  (скилл `assets`); ничего не подбирать «на глазок».
* Внешний архив `D:\gameMake\ZnT-1\ZNT_TEST\PS2_GAME\` — в git не входит.

## 9. Короткий самоконтроль перед правкой

1. Правлю по JA-доказательству или по предпочтению? (нет доказательства → `???`)
2. Это добавление или переписывание работающего? (переписывание → обоснование + журнал)
3. Есть classification + disposition? (нет → вернуться к §3)
4. Не блокирую ли я больше минимума? (§4)
5. Кириллица/японский ушли файлом, а не командой? (§5)
6. Коммит не требуется? (§6)
