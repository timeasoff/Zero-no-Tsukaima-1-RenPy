# ps2-source — чтение и разбор источника PS2

JA — **канон смысла** (`AGENTS.md` §1). Этот скилл описывает, как канон лежит в
`ps2_source/`, как его правильно читать и как резать главу на части. Он ничего
не меняет в проекте — только читает источник.

## 1. Карта `ps2_source/`

```text
ps2_source/
  chapters/chapter_NN_<яп>.txt        32 файла — ЧИТАЕМЫЙ вид, порядок источника  ★ основной вход
  events_full/chapter_NN_<яп>.txt     32 файла — ВСЕ вызовы с сырыми аргументами  ★ точный вход
  scripts/SCENE_%04d.txt              1920 файлов, сырой CP932 (контекст if/for/while)
  chapter_map.txt                     таблица глав: ядро сцен / talk / set / trans / choice
  chapter_stats.json                  то же в JSON (сумма talk = 17 282)
  all_dialogues.txt                   все 17 282 реплики подряд по главам
  README.txt                          описание форматов (по-японски/по-английски)
  _diagnostics/                       готовые отчёты: crosswalk.json, scene_label_crosswalk.json,
                                      resource_map.txt, chapter_line_grammar.txt, bgm_check.txt,
                                      voice_scene_map.json, final_verify.txt, …
```

Кодировка: исходники — **Squirrel, Shift-JIS (CP932)**; `ps2_source/*.txt` — уже
декодированный UTF-8. Происхождение данных и метод восстановления — `EXTRACTION_METHOD.md`.

**Два входа работают в паре:** `chapters/` даёт порядок и читаемость, `events_full/`
даёт точные аргументы (`set/next/selectItem/dateItem/moveItem/like`). Спорный случай
решается по `events_full/`, а спор о том, «что именно сказано», — по JA в обоих.

### Генераторы `_diagnostics/` (внешние скрипты)

Отчёты `_diagnostics/` создаются скриптами во внешнем архиве
`D:\gameMake\ZnT-1\ZNT_TEST` (запуск: `python <имя>` из его корня; в git не входят):

| скрипт | что даёт |
|---|---|
| `crosswalk.py` | главный: `.rpy` ↔ сцены PS2, `jump/call`, инвентарь `*_fx`, структура PS2 внутри сцен, `voice` → сцена → PS2-id → JA. **Расширяй** его после добавления новых `.rpy` |
| `resource_probe.py` | id BGM/SE/картинок, где используются какие `tN` и `play sound`, раскладка `game/images`, `image`-инструкции |
| `resource_probe2.py` | значения `level`, слои `set()`, `dir`, `trans()` |
| `bgm_check.py` | доказательство правила BGM `t{K-1}` |
| `voice_csv_index.py` | сверка `transcriptions_ja_ru.csv` с PS2-голосами («дырки» = портированные) |
| `line_grammar.py` | все формы строк `chapters/*.txt` + словарь говорящих |
| `extract_final.py`, `verify_final.py` | регенерация и проверка самой выборки (`verify ok=True`) |

Ключевые отчёты уже скопированы в `ps2_source/_diagnostics/`: `crosswalk.txt|json`,
`scene_label_crosswalk.txt|json`, `voice_scene_map.json`, `chapter_line_grammar.txt`,
`resource_map.txt`, `resource_map2.txt`, `bgm_check.txt`, `voice_csv_index.txt`,
`voice_csv_status.txt`, `scene_graph.txt|json`, `correspondence.txt`, `final_verify.txt`.
Пересоздание основного набора: `python crosswalk.py && python resource_probe.py && python bgm_check.py`.

## 2. Формат `chapters/*.txt`

Шапка файла:

```text
========================================================================
CHAPTER 02 : ゼロのルイズ
core scenes : 6 .. 67  (62 scenes)
extra scenes: 1009..1255  (56)
========================================================================
```

Далее разделители сцен `---- SCENE 0006 ----` и по одной сущности на строку.

### 2.1 Реплики

```text
サイト：よろしく頼む。  [voice 15898]                      ← говорящий + '：' + текст + [voice N]
（ルイズが頬を膨らませた）  [voice 15901]                   ← мысли/нарратив в （ ）
兵士Ｂ：は、大通りに面した通りで数回、
爆薬による爆発が確認されています。  [voice 4291]           ← вторая физическая строка БЕЗ отступа
```

Правила разбора:

* разделитель говорящего — **полная-width двоеточие `：` (U+FF1A)**, не `:`;
* реплика может занимать несколько физических строк; дочерние строки идут **с начала
  строки** (без отступа) и содержат только текст;
* тег `[voice N]` стоит **только на последней физической строке** реплики и является
  признаком её конца;
* мысли всегда обёрнуты в полные скобки `（ … ）` — в EN/RU они рисуются окном `th`
  и скобок не требуют (`game/PROMTS.md` п.8);
* говорящий `null` (104 реплики) — безымянный нарратив/мысли;
* **одна реплика источника = одна строка EN-строки сценария**; переносы склеиваются
  в одну, содержание не меняется (пример склейки — `game/tl/japanese/dialogs.rpy`
  `new "は、大通りに面した通りで数回、爆薬による爆発が確認されています。"`).

### 2.2 Скобочные события (с префиксом два пробела)

```text
  [TITLE title("ゼロのルイズ")]                      ← заголовок (не реплика!)
  [BG       stage    image=+60, level=200]          ← фон
  [BG       stage    hide] / [BG stage hide, reset] / [BG stage vibrate=21]
  [EVENT_CG event    image=+148, level=80]          ← CG
  [SPRITE   lay5     image=+390, level=160, dir=1A] ← спрайт в слоте lay1..lay40
  [SPRITE   lay17    hide] / [SPRITE lay5 x=224, y=0] / [SPRITE lay1 reset]
  [LAYER    white   image=+2, level=0]              ← вспышка; [LAYER lay0 …] — оверлей-слой (994 вызова)
  [BGM      bgm      play=+19]                      ← музыка
  [BGM      bgm      stop=1000]                     ← fadeout, мс
  [SE       se0      play=+63]  / [SE se1 stop=1]
  [TRANS    trans("crossfade", 1000)]               ← переход, мс (в игре только crossfade)
  [VIBRATE  vibrate(3)]                             ← тряска
  [MOVIE    movie(0)]                               ← видео
  [COFFEE]                                          ← пауза (в ремастере → $ pause(1.0))
```

`[WAIT …]` в `chapters/` **не рисуется** — паузы `waitTime(ms)` видны только в
`events_full/` как `WAIT       waitTime(1200, true)`. Не считай их отсутствие
отсутствием паузы в источнике.

### 2.3 Ветки, переходы, симпатия

```text
  【選択肢】いいと思うぜ → scene 7                    ← selectItem (мелкий выбор)
  【デート】ルイズ → scene 1009                      ← dateItem
  【デート進行】 → scene 1865                        ← date()
  【移動】シエスタの部屋 → scene 489  ((0x01000000 +1224))   ← moveItem
  【好感度】ルイズ  10                                ← like(), бывает и «-10»
  → next scene 68                                    ← безусловный переход next()
  extra scenes: 1009..1255  (56)                     ← служебная пометка, не код
```

⚠️ **Ловушка `【移動】`:** первое число после `→ scene` — это **не номер сцены**, а
id картинки карты `(0x02000000 +489)`; реальная цель перехода записана в двойных
скобках `((0x01000000 +1224))`. Проверено по `events_full`:
`MAPDEST    moveItem("シエスタの部屋", (0x02000000 +489), (0x01000000 +1224))`.
Для `【選択肢】`/`【デート】`/`→ next scene` номер после `→ scene` — настоящая цель
(`CHOICE selectItem("いい思うぜ", (0x01000000 +7), null, true)`).

## 3. Формат `events_full/*.txt`

Разделитель `## SCENE 0006`, далее строки «префикс + сырый вызов»:

```text
SET        set("stage", {opacity = 100,y = 0,show = 1,level = 200,x = 0,image = (0x02000000 +85)})
TRANS      trans("crossfade", 1000)
SET        set("bgm", {play = (0x03000000 +19)})
DIALOGUE   talk("サイト", null, "よろしく頼む。", (0x04000000 +15898))
CHOICE     selectItem("シエスタ", (0x01000000 +1014), null, true)
DATE       dateItem("ルイズ", (0x01000000 +1009))
GOTO       next((0x01000000 +68), true)
LIKE       like("ルイズ", 10)
MAPDEST    moveItem("廊下", (0x02000000 +852), (0x01000000 +1234))
TITLE      title("ゼロのルイズ")
WAIT       waitTime(1200, true)
```

**Две сигнатуры `talk()`:**

| сигнатура | вид | где |
|---|---|---|
| `talk(голос, отображаемое, текст, голосовой_id)` — 4 арг. | `talk("兵士Ａ", "兵士", "どこで爆発だ！", (0x04000000 +4283))` | основной случай; второй арг. бывает `null` |
| `talk(голос, текст, голосовой_id)` — 3 арг. | `talk("サイト", "（そうだな…）", null)` | **сцены 63–67** главы 02 |

Объявление движка `talk(name, disp, text, voice)` в **сцене 3 — пропускать**.

Прочие префиксы, встречающиеся в потоке: `if  if(isJump())`, `voice  voice((0x04000000 +5016),"ルイズ")`,
`waitVoice  waitVoice()`, `endSkip  endSkip()`. Полный список событийных префиксов:
`DIALOGUE SET TRANS GOTO CHOICE DATE TITLE WAIT MSGON MSGOFF BACK RESET LIKE ITEM MOVIE
VIBRATE CREATE SYNC MENU MENUINIT TNDL MAPDEST MOVE MOVEINIT COFFEE SKIP RESETSEL DECL`.

**Коды ссылок:** `(0x01000000 +N)` сцена, `(0x02000000 +N)` картинка,
`(0x03000000 +N)` BGM/SE, `(0x04000000 +N)` голос.

## 4. CP932-подвохи (при написании парсеров)

* канва `、` в CP932 = байты `0x81 0x5C`, а `0x5C` — это `\` → наивный разбор
  «экранирования» и разбиение по запятым **ломается**;
* старшие байты двойных символов: `0x81–0x9F`, `0xE0–0xFC` — их нельзя считать
  одиночными (кавычка внутри японского текста — не кавычка);
* разбиение аргументов — только по запятым на глубине 0, со строками, `(){}[]`
  (готовый пример — `EXTRACTION_METHOD.md` §3);
* `python -c "…"` с кавычками/переносами ломается, PowerShell здесь cp1251:
  японский/русский в консоль **не печатать**; результат писать в UTF-8 файл.

## 6. Порядок обхода главы

1. Прочитать **всю** `ps2_source/chapters/chapter_NN_*.txt` целиком — это границы главы.
   Строка `extra scenes: …` границей главы **не** является (см. §8).
2. Прочитать `ps2_source/events_full/` той же главы — точные `set/next/selectItem/
   dateItem/moveItem/like`.
3. Выписать структуру: локации (`[BG stage image=…]` после завершённых блоков),
   `→ next scene`, ветки `【選択肢】/【デート】/【移動】`, ветки в `extra scenes:`.
4. Разрезать на части (§7), назначить лейблы, связать `jump`.
5. Портировать по порядку внутри части: `*_fx` → `voice` → реплика (EN) →
   `menu`/`*_choice` → `jump`, параллельно дописывая `old/new` в оба `tl/`.

## 7. Резка главы на части (детерминированный алгоритм)

Ориентир — глава 1: 10 частей / 1244 реплики / 1154 голосовых ≈ **115 голосовых на часть**.

1. Целевой размер части — **115 ± 25 голосовых** (90…140). Считать `[voice N]` в
   `chapters/*.txt` (это же число = число `voice "…"` в готовой части).
2. Резать только на **сильной границе**, в порядке приоритета:
   * `→ next scene N` — сильнейшая граница;
   * смена локации: `[BG stage image=…]` после завершённого блока реплик;
   * конец ветки `【移動】` / `【選択肢】` / `【デート】` (не середина ветки).
3. Окно: резать при накопленных **≥ 90** голосовых; приоритет — первая сильная
   граница после **115**; если к **140** сильной границы нет — резать по ближайшей
   слабой (смена фона); **раньше 90 не резать**.
4. Уже разрезанные главы **не перерезаются** (глава 1 задана: `script-ch1_1..10.rpy`).

Именование (фиксировано, не изобретать):

```text
файлы   game/chapters/<N>/script-ch<N>_1.rpy, script-ch<N>_2.rpy, …
лейблы  ch<N> (часть 1), ch<N>_2, ch<N>_3, …
локации <loc>_ch<N>_<M>          (si_room_ch1_3, hallway_ch1_8, library_ch1_8)
конец   jump ch<N>_<M+1>          (конец главы — jump attention)
```

## 8. `extra scenes:` и спец-события

* `extra scenes:` — **не код и не граница главы**: это перечень сцен, приклеенных
  главе back-trace'ом (свидания и ветки, предложенные этой главой).
* Реплики из таких сцен портируются **в той же части**, где встретились, **своим
  лейблом внутри неё** — образец: `date_louise_1`, `date_siesta_1` … в
  `game/chapters/1/script-ch1_10.rpy`.
* `chapter_90` / `chapter_91` (сцены 1533–1860, тундэре/дэре) — отдельная папка
  `game/chapters/extra/` (`sp_l1.rpy` уже частично); в PS2 они вызываются вычислением
  `(tun ? tnEventId : dlEventId) + 2 + no*3 + event[no]` из `getTunDeleScene()`,
  статических ссылок на них нет; таблица `dlEventId/tnEventId → label` ведётся
  в `references/` по мере появления.

## 10. Проверь перед тем, как опираться

* Формы строк — `_diagnostics/chapter_line_grammar.txt` (там 13 450 distinct-форм
  с примерами); не выдумывай форму, которой нет в этом отчёте или в самом файле.
* Числа глав/сцен — `chapter_stats.json`, а не память.
* Точная сигнатура вызова — `events_full/`, а не читаемый вид.
* Если факт о грамматике не подтверждается ни файлом, ни `_diagnostics/` — так и
  напиши в отчёте («JA прямо этого не подтверждает», пометка `???`).
