# Сохранение результата

Единица сохранения — **порция части главы**. Результат пишется **прямо в файлы
проекта** инструментами записи (write/edit) и проверяется прочтением (read).

Промежуточных каталогов и скриптов сохранения в проекте больше **нет**:
`output/`, `translates/`, `merged/`, `scripts/save_block.py`,
`scripts/update_merged.py`, `scripts/fix_block.py` — не ищи их и не создавай
по привычке. Источник JA (`ps2_source/`) — только для чтения.

**Сохранение прогресса ≠ git-коммит** (см. «Git» в конце файла).

## Что входит в порцию

```text
game/chapters/<N>/script-ch<N>_<M>.rpy   ← EN-строки + voice, *_fx, menu, jump (база)
game/tl/japanese/<bucket>.rpy            ← translate japanese strings: old "EN" / new "JA"
game/tl/russian/<bucket>.rpy             ← translate russian strings:  old "EN" / new "RU"
transcriptions_ja_ru.csv                 ← если в порции работали голоса
reports/ch<N>/<part>.md                  ← отчёт части
reports/log.md                           ← дозапись решений/сомнений (не переписывание)
```

Бакеты `tl/` плоские: `dialogs`, `thoughs`, `choises`, `common`, `overlays`,
`characters`, `options`, `screens` (AGENTS.md, §6). Тройка файлов «сценарий +
оба tl» правится **синхронно**: у каждой новой EN-строки в тот же проход
появляются пары `old/new` и в `tl/japanese`, и в `tl/russian`.

Порция = одна часть главы (или её осознанный участок, если часть большая:
правки дописываются в те же файлы, единица работы не меняется).

## Порядок порции

1. **Самопроверка перед записью** — скилл `self-review`, после каждой
   правки и непосредственно перед каждой записью. Запись без самопроверки
   запрещена.
2. **Запись файлов порции**: `script-ch<N>_<M>.rpy` → `tl/japanese` →
   `tl/russian` (все три — одной порцией, без «допишу потом»).
3. **Контроль записи**: перечитай каждый записанный файл (см. ниже).
4. **Журнал**: сомнения, удаления, `PROVISIONAL`, `???` — дозаписью в
   `reports/log.md` в этот же момент, а не «потом».
5. **Проверки**: `python tools/check_project.py` → `RESULT: OK`
   (итог — `reports/check_project.md`), закрытие чек-листа
   `project-checks`.
6. **Отчёт части**: `reports/ch<N>/<part>.md` по шаблону AGENTS.md, §8.

## Прямая запись

* Пиши инструментами записи **напрямую** в файлы проекта; промежуточных
  `output/`, `tmp/`, merged-копий не создаётся.
* Кириллицу и японский **не передавай** в аргументах командной строки и через
  конвейеры shell, не печатай их в PowerShell (здесь cp1251 — канал искажает
  символы). Читай файлы инструментом read, пиши — инструментом write/edit.
* Перед редактированием существующего файла прочитай его: правь по точному
  фрагменту (edit), не переписывай файл целиком без нужды.

## Контроль записи (после каждой записи)

1. **Перечитай записанный файл.** Не должно быть `?` вместо букв, подменённых
   символов, сломанных кавычек и отступов. Кириллица в UTF-8 занимает 2 байта —
   если файл сохранился без многобайтовых символов, текст испорчен кодировкой:
   перезапиши.
2. **`old` дословно равен строке сценария** (EN из `.rpy`): то же написание,
   кавычки, многоточия, регистр, `{i}…{/i}`. Расхождение на символ — перевод
   Ren'Py **молча не применится**. Один и тот же `old` не должен встречаться
   дважды в одном языковом файле (при дубликате применяется только первая
   пара `old/new`).
3. **Структура `tl`-файла**: блок `translate <language> strings:` с отступом
   4 пробела, пары `old`/`new` без пропусков и нарушений порядка.
4. **Уникальность**: все `from _call_overlay_screen_K` и все `label`
   уникальны во всём проекте (закрывается `tools/check_project.py` — но
   беглый взгляд при записи не помешает).
5. Молча оставлять предупреждения проверок нельзя: каждое — в журнал или в
   отчёт части с решением.

## Самопроверка перед записью

Перед каждой записью выполняется полный чек-лист скилла `self-review`:
полнота, отсутствие добавлений, отсутствие искажений, сохранение модальности,
имена и термины по `dictionary.md`, обращения по `addresses.md`, речь и
оформление, читаемость, грамматика, соответствие JA. Пары сверки:
**JA → EN** (строка `.rpy`) и **JA → RU** (строка `tl/russian`).

## Что никогда не переписывается

* `ps2_source/**` — канон JA, только чтение.
* Работающая архитектура эталонных глав 0 и 1 (цепочки `jump`, имена
  `voice`, `*_fx`, `menu`): текстовые правки возможны только с записью в
  `reports/log.md` и прогоном `tools/check_project.py` (AGENTS.md, §1).
* Ранее сохранённые порции частей — без явной команды пользователя не
  переписываются; работа — добавлением.
* Evidence-файлы `reports/sma/**/{a,b,c,precheck,analysis}/` — история
  аудита, не редактируются и не удаляются.
* `reports/log.md` — **только дозапись**; журнал не переписывается и не
  сокращается.
* `dictionary.md`, `addresses.md` — строки добавляются, чужие записи не
  переписываются и не удаляются.
* **Молча ничего не удаляется.** Любое удаление/сокращение/расхождение
  JA ↔ EN ↔ RU — запись в `reports/log.md` и пометка `???` в отчёте части,
  если нужно решение человека.

## Восстановление после сбоя

Прогресс = сами файлы части (никаких маркеров блоков). Определи, что уже
сделано: какие реплики уже в `script-ch<N>_<M>.rpy`, какие пары `old/new`
уже в обоих `tl/`, написан ли отчёт. Продолжай с первой непортированной
реплики части (следующий `voice`/реплика + соответствующие `old/new`).
Утраченная запись восстанавливается из JA-источника; границы части (`jump`
на следующую часть, `jump attention` в конце главы) не меняются.
Число частей и их имена детерминированы (AGENTS.md, §3) — это и есть
контроль целостности.

## PROVISIONAL при сохранении

Неподтверждённые решения (новый термин, рабочая форма обращения, спорное
место) **не блокируют** сохранение порции: записывай выбранную форму,
внеси запись в `reports/log.md` с пометкой `PROVISIONAL` и перечнем мест
использования, укажи в отчёте части. UNCERTAINTY ≠ STOP, PROVISIONAL ≠
CANONICAL, PROVISIONAL ≠ WAIT. Места, требующие решения человека, —
пометка `???` в отчёте части + запись в журнал; текст при этом сохраняется
как есть.

## Git

**Единое правило приоритетом над всеми локальными инструкциями:** `git
commit` выполняется **только после явного подтверждения пользователя на
конкретный набор изменений**. Успешные проверки, отчёты, просьба «сохранить
прогресс» и общее разрешение редактировать файлы — **не** разрешение на
коммит. Запрет действует и для подагентов.

* Предложить коммит можно: назвать сообщение и перечень изменений.
* Без подтверждения изменения остаются незакоммиченными.
* `git status`, `git diff`, `git log`, `git show`, сравнение ревизий —
  разрешены.
* Медиа (`audio`, `gui`, `images`, `video`, все `*.ogg/*.png/*.webp/*.wav/
  *.webm`) в git не входят — это `.gitignore`; новые голоса живут в
  `game/audio/voices/` локально и в облачном архиве (AGENTS.md, §5,
  «Git vs медиа»).
