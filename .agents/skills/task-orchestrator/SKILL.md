# task-orchestrator — оркестрация свободных задач

Роль: ведущий агент получает задачу свободной формы от пользователя и сам
разбирает её на подзадачи, сам запускает субагентов с готовыми промптами,
сам проверяет, что реально выполнено. Ручное управление сведено к минимуму:
пользователь формулирует цель, доска и проверки ведутся на диске.

## 0. Персистентность (главное свойство системы)

Вся память о задаче живёт НЕ в контексте сессии, а на диске:

* `reports/task_board.json` — машиночитаемое состояние (в git);
* `reports/task_board.md` — зеркало для человека (`task_board.py sync`);
* `reports/tasks/<task>/<sub>.result.md` — result-маркер субагента;
* `reports/tasks/prompts/<task>_<sub>.md` — сгенерированные промпты (gitignore).

Поэтому компактизация контекста и обрыв связи ничего не теряют: состояние
читается заново командой `status`/`check`.

## 1. Первый шаг любой сессии — восстановление

```
python tools/task_board.py status
```

* Если есть открытая задача — продолжаешь ЕЁ, а не берёшь новую.
  Затем обязательная диагностика обрыва:

  ```
  python tools/task_board.py check <task>
  ```

  `check` ничего не меняет и для каждой незакрытой подзадачи выносит вердикт
  строго по диску:

  | вердикт | что на диске | действие |
  |---|---|---|
  | `READY` | маркер `STATUS: DONE` | `done <task> <sub>` |
  | `PARTIAL` | маркер `STATUS: PARTIAL` | продолжить субагента (см. §4) |
  | `ORPHANED` | `started` есть, маркера нет | обрыв — продолжить сессией либо перезапустить |
  | `PENDING` | ещё не запускалась | `next` |

* Если открытых задач нет — создать новую под полученную задачу (§2).

## 2. Приём задачи и декомпозиция

```
python tools/task_board.py new --request "<текст пользователя>" [--target 4]
```

Цель (`--target`) — по форме `tools/targets.py`: `4` | `4_6` |
`script-ch4_6.rpy` | `extra`. Затем собери декомпозицию по реальному
состоянию проекта (не по памяти!):

1. `reports/translation_plan.md` — что сделано и что дальше;
2. `python tools/agent_workflow.py --action chapter-state --chapter <N>`;
3. `python tools/agent_workflow.py --action phase-checklist --chapter <N>`
   (+ `--scope chapter` для проверочных задач);
4. `python tools/check_project.py` → `reports/check_project.md`;
5. при сомнениях в границах — источники `ps2_source/` (скилл `ps2-source`).

Каждая подзадача записывается отдельно (потеря при обрыве исключается):

```
python tools/task_board.py sub-add <task> --prompt <prompt-id> --target <цель> \
    [--scope chapter] [--title "коротко, что делаем"]
python tools/task_board.py sub-add <task> --manual "текст работы без промпта" \
    [--target <цель>]
```

`prompt-id` — из `python tools/agent_workflow.py --list`. Типовые наборы:

* **«перевод главы N продолжить»**: `continue`/`port-part` на текущую часть →
  по кругу `port-part` на следующие части (последовательно, один файл — одна
  подзадача) → `voice-work` → `full-audit` → `check-project` (manual);
* **«проверка главы N целиком»**: `semantic-audit-a --scope chapter`,
  `pragmatic-c --scope chapter`, `analyzer-phase1 --scope chapter` (параллельно,
  фоном) → после их маркеров `analyzer-phase2 --scope chapter` →
  `full-audit`/`grammar-audit`/`style-audit`/`humanizer` по необходимости;
* **«проверка конкретных чанков»**: те же проверочные промпты, но по каждой
  части (`3_2`, `3_5`) отдельной подзадачей — так evidence ляжет в
  `reports/sma/ch3/2/` и `reports/sma/ch3/5/`.

## 3. Исполнение подзадачи (цикл)

```
python tools/task_board.py next <task>          # точные команды следующей подзадачи
python tools/task_board.py start <task> <sub> --session <sessionID>
```

Порядок одного круга:

1. `next` печатает готовую команду генерации промпта с `--out`
   (у каждого субагента свой файл — параллельные запуски не затирают друг
   друга). Выполни её.
2. Запусти субагента (инструмент запуска субагентов харнеса). Промпт субагента:
   полный текст задания из файла `reports/tasks/prompts/<task>_<sub>.md`
   **+ обязательный ПРОТОКОЛ ЗАВЕРШЕНИЯ** (текст:

   ```
   python tools/task_board.py contract <task> <sub>
   ```

   возвращает готовую приписку; приложи её дословно к заданию субагента).
3. Как только субагент запущен и вернул `sessionID` — зафиксируй его:
   `start ... --session <sessionID>`. Если возврата не было (обрыв сразу) —
   `start` без `--session`, это не блокирует.
4. Завершение субагента проверяй НЕ по его словам, а по диску:
   `check` → `READY` → `done` (по возможности с `--evidence <пути>`).

### Протокол завершения (контракт субагента)

Каждый субагент получает в задании приписку из `contract`: он обязан по
завершении (успех, частичный результат или невозможность закончить) записать
result-маркер `reports/tasks/<task>/<sub>.result.md` со структурой
STATUS / СДЕЛАНО / ФАЙЛЫ / ПРОВЕРКИ / ОСТАЛОСЬ / ВОПРОСЫ. Маркер —
единственное доказательство завершения. Субагенту запрещено трогать
`reports/task_board.json` — доску ведёт только ведущий агент.

## 4. Обрыв связи со субагентом (обязательная процедура)

Субагенты могут не вернуться (обрыв коннекта, падение, компактизация у
них самих). Это НЕ ошибка оркестрации — процедура стандартная:

1. `python tools/task_board.py check <task>` — вердикт по диску.
2. `PARTIAL` (маркер есть, но STATUS: PARTIAL):
   * есть `session` — продолжи ТУ ЖЕ сессию субагента (инструмент
     продолжения субагента, `sessionID` из доски) приказом вида:
     «Продолжай задачу `<sub>`; дочитай свой маркер `<path>` и закрой
     раздел ОСТАЛОСЬ; маркер обнови»;
   * нет `session` — перезапусти по промпту с приказом «доделай по маркеру
     `<path>`».
3. `ORPHANED` (маркер отсутствует, но `started` есть — оборвали до записи):
   * есть `session` — продолжи сессию приказом: «Продолжай задачу `<sub>`;
     если работа утеряна — перечитай задание из `<prompt-file>` и выполни
     заново; маркер обязательно запиши»;
   * нет `session` — чистый перезапуск: `next` → сгенерировать промпт →
     запустить заново.
4. После восстановления — снова `check`, и только `READY` закрывается `done`.

Правило: к новым подзадачам не переходи, пока есть `PARTIAL`/`ORPHANED`
(исключение — явно параллельные запуски: см. §5).

## 5. Параллелизм и последовательность

* **Параллельно (фоном)**: изолированные аудиторы — `semantic-audit-a`,
  `pragmatic-c`, `analyzer-phase1` (каждый пишет в свой каталог, конфликтов
  нет). Запускай их подзадачами сразу после декомпозиции; вердикты по ним —
  по маркерам через `check`.
* **Только после** маркеров всех аудиторов: `analyzer-phase2` (он читает
  их evidence целиком).
* **Строго последовательно**: всё, что пишет в один и тот же файл
  (script одной части, оба `tl/`); каждый `port-part` — отдельная подзадача
  и отдельный `done` до старта следующей.
* `full-audit` и языковые слои (`grammar`/`style`/`humanizer`) после того, как
  смысловая часть закрыта (`analyzer-phase2`).

## 6. Дисциплина done / close

* `done` ставится ТОЛЬКО после `check` с вердиктом `READY` (маркер на диске)
  и по возможности после `verify` (сверка артефактов: evidence-каталоги SMA,
  отчёт части, script-файл, mtime после старта):

  ```
  python tools/task_board.py verify <task>
  python tools/task_board.py done <task> <sub> --evidence reports/... ...
  ```

* Закрытие задачи:

  ```
  python tools/task_board.py close <task>
  python tools/task_board.py sync
  ```

  `close` отказывается закрывать задачу с незакрытыми подзадачами (без
  `--force`). После `close` — обновить `reports/translation_plan.md`,
  запись в `reports/log.md`, предложить пользователю коммит (коммит — только
  с явного подтверждения, AGENTS.md §5).

* Субагент не «закрывает» работу словами: если его отчёт говорит «готово»,
  а маркера нет — это `ORPHANED`, и подзадача докрывается по §4.

## 7. Пример: «продолжи перевод главы 4»

```
python tools/task_board.py status
python tools/task_board.py new --request "Продолжить перевод главы 4" --target 4
python tools/task_board.py sub-add T... --prompt continue --target 4_6 --title "Доделать часть 6"
python tools/task_board.py sub-add T... --prompt port-part --target 4_7 --title "Часть 7"
python tools/task_board.py sub-add T... --prompt full-audit --target 4_6 --title "Аудит части 6"
python tools/task_board.py sub-add T... --manual "check_project.py до OK" --target 4
python tools/task_board.py next T...        # -> команда промпта для S1
... сгенерировать промпт, запустить субагента, start --session ...
python tools/task_board.py check T...       # обрыв? -> READY / PARTIAL / ORPHANED
python tools/task_board.py done T... S1
... следующая подзадача ...
python tools/task_board.py close T...
python tools/task_board.py sync
```

## 8. Ограничения роли

* git commit, удаления файлов, правки `ps2_source/` и JA-строк — по AGENTS.md
  (§5), оркестрация ничего не отменяет.
* Все смысловые решения по тексту — по скиллам `tl-en-ru`, `russian-*`,
  `terminology-dictionary`, `forms-of-address`; эта система — только
  разбиение, запуск и учёт.
* Доску пишет только ведущий агент; субагентам она запрещена (это в их
  протоколе завершения).
