# tl-en-ru — перевод: EN-база в сценарий, JA/RU в `tl/`

## 1. Языки и куда что пишется

```text
JA = канон смысла          ps2_source/chapters/*.txt
EN = базовый язык ремастера  → ПИШЕМ МЫ из JA в game/chapters/<N>/script-ch<N>_<M>.rpy
RU = перевод               → ПИШЕМ МЫ из JA в game/tl/russian/*
```

**Готового английского перевода в источнике нет.** EN — не «чужой эталонный перевод»,
а наш текст в самом сценарии. Поэтому:

* смысл проверяется по парам **JA → EN** и **JA → RU**;
* **JA > EN** и **JA > RU** при любом конфликте;
* расхождение EN ↔ RU **не решается молча**: если обе формы проходят по JA, но
  трактуются по-разному → флаг `RECONCILE` в `reports/log.md`; если по JA одна из
  форм неверна — правится эта форма;
* совпадение RU с EN само по себе **не доказательство** (доказательство — JA).

Тройка файлов каждой части (меняются синхронно):

```text
game/chapters/<N>/script-ch<N>_<M>.rpy    EN-текст, voice, *_fx, menu, jump   (база)
game/tl/japanese/<bucket>.rpy             translate japanese strings:  old "EN" / new "JA"
game/tl/russian/<bucket>.rpy              translate russian strings:   old "EN" / new "RU"
```

## 2. Бакеты `tl/<язык>/` (плоские, на весь проект)

| файл | что туда идёт |
|---|---|
| `dialogs.rpy` | обычные реплики (`s "…"`, `l "…"`) — основной объём |
| `thoughs.rpy` | мысли (`th "…"`) |
| `choises.rpy` | тексты пунктов `menu:` и `*_choice` |
| `overlays.rpy` | тексты `call overlay_screen(...)` (заголовки глав/локаций) |
| `common.rpy` | строки экранов, кнопок, общего UI |
| `characters.rpy` | отображаемые имена (`define s = Character(_("Saito"), …)`) |
| `options.rpy`, `screens.rpy` | прочее UI |

Бакеты остаются **плоскими** (`AGENTS.md` §6). Если бакет разрастётся, допустимо
разбить на файлы **внутри того же** бакета (`dialogs_ch3.rpy`), но **одинаковый `old`
не должен встречаться дважды** — иначе перевод молча не применяется.

## 3. Формат записи

```renpy
# game/tl/japanese/dialogs.rpy
translate japanese strings:
    old "Where did the explosion happen?"
    new "どこで爆発だ！"

# game/tl/russian/dialogs.rpy
translate russian strings:
    old "Where did the explosion happen?"
    new "Где произошёл взрыв?"
```

Обязательные условия:

* **`old` дословно совпадает со строкой сценария** (после раскрытия `\"`), включая
  `…`, `—`, `{i}…{/i}`, невидимые `\u00A0` и т. п. Иначе перевод молча не применяется
  и в игре остаётся английский. Если в JA/RU-режиме строка осталась английской —
  **чини `old` в `tl`, а не сценарий**;
* заголовок блока — `translate japanese strings:` в `tl/japanese/` и
  `translate russian strings:` в `tl/russian/` (нарушение = **E8**);
* `new ""` пустым не бывает (**E6**);
* **каждая новая EN-строка обязана получить `old/new` в обоих языках** (`E4`/`E5`);
* порядок пар внутри бакета — по мере появления (эталоны держат порядок сценария).

Известные расхождения старых `old` уже есть (например, в `thoughs.rpy` часть `old`
записана с дефисом вместо `—` и без акцентов: `Francoise` против `Françoise`) — это
**W1**-кандидаты; чинятся на стороне `tl`.

## 4. Правила перевода (`game/PROMTS.md`, обязательны)

1. **3 варианта перевода**, явно указать, какой самый точный, какой больше подходит
   по смыслу, и **почему**. Стараться соблюдать оригинал, не своевольничать.
2. Сравнивать новые строки с уже переведёнными в рамках контекста (перевод идёт
   линейно и построчно).
3. Если в контексте обнаружена **некорректно переведённая старая строка** — указать
   и предложить исправление (с записью в `reports/log.md`).
4. Обращения **«-сан» и прочие сохранять**, если они есть (плюс `dictionary.md` /
   `addresses.md`).
5. Много точек `......` → заменять на троеточие `…`.
6. `old` — то, что переведено (EN); `new` — оригинал (JA) в `tl/japanese`;
   в `tl/russian` `new` — русский перевод.
7. Обороты «нет так ли?», «верно?» в конце предложения в русском употребляются
   **реже**, чем `isn't?`/`right?` в английском — не тащить кальку.
8. Мысли обычно обозначаются **полностью круглыми скобками `（…）`**; для EN и RU
   такие скобки **не нужны** (окно `th` рисует их само).
9. Реплики — в двойных кавычках `"…"`; внутренние двойные кавычки — через `\"`.
10. Цитаты внутри реплик — кавычки **соответствующего языка**: в русском `«»`,
    в английском `''`.
11. Записанные **действия** (например «зевнул») оборачивать в `{i}…{/i}`; **не додумывать**
    действия там, где их нет в оригинале.
12. Текст для перевода считается **без опечаток**: кажущаяся опечатка может быть
    намеренным приёмом повествования.
13. По возможности оставлять пометки к переводу.

Дополнительно из практики проекта:

* в EN и RU **троеточие** `......` → `...`/`…`, «-сан» и прочие обращения сохраняются;
* `old` (EN) должен оставаться тем же, что в сценарии, — правки EN после появления
  `old` требуют синхронной правки **обоих** `tl`.

## 5. Японский (`tl/japanese`, `new` — канон)

* брать **дословно** из `ps2_source/chapters/*.txt`;
* **склеивать** физические переносы реплики в одну строку:
  `は、大通りに面した通りで数回、` + `爆薬による爆発が確認されています。` →
  `new "は、大通りに面した通りで数回、爆薬による爆発が確認されています。"`;
* мысли остаются в **полных скобках `（…）`** (в EN/RU — без них, п.8 `PROMTS.md`);
* не «улучшать» JA: это канон, а не черновик.

## 6. Словари и обращения — обязательная сверка

* **Термины, имена, названия, заклинания** — только `dictionary.md`
  (скилл `terminology-dictionary`): словарная запись — каноническая идентичность
  термина, а не механическая замена.
* **Форма обращения** — `addresses.md` (скилл `forms-of-address`): используется
  **уже установленная** форма; новое обращение из воздуха не создаётся.
* Новый термин, не подтверждённый словарём → `PROVISIONAL` в `reports/log.md`
  (не записывать в `dictionary.md` как канон), см. `project-constraints`.
* Словари дописываются **добавлением**; правка уже утверждённого — через журнал.

## 7. Порядок работы над переводом части

1. Написать EN в `.rpy` по JA (сначала `*_fx`, потом `voice`, потом реплика,
   `menu`/`*_choice`, `jump` — см. `renpy-remaster-api`).
2. Параллельно дописывать `old/new` в `tl/japanese` и `tl/russian` в правильном бакете.
3. Прогнать `python tools/check_project.py`: E4/E5 (нет `old` в одном из языков),
   E6 (пустой `new`), E8 (не тот язык), W1 (протухший `old`).
4. Смысловые аудиты: `translation-audit` (JA→EN и JA→RU по смысловым фрагментам),
   затем независимые `semantic-audit-a` / `semantic-audit-b` и сводка
   `semantic-analyzer` — evidence ложится в
   `reports/sma/ch<N>/<part>/{a,b,c,precheck,analysis}/`.
5. Русская сторона: `russian-humanizer` → `russian-prose-rules` →
   `russian-grammar-control` → `russian-style-audit` (каждый ищет свой класс дефектов,
   слои не подменяют друг друга).
6. Самопроверка на галлюцинации/пропуски перед каждой записью (`self-review`),
   затем запись файлов и отчёт части.

## 8. Частые ошибки

* `old` переписан «для красоты» → перевод перестал применяться (чинить `old`).
* `new` в `tl/russian` скопирован из EN → русский режим показывает английский.
* JA-строка склеена **с потерей** символа (например, `　` —ideographic space в начале
  продолжения) → свериться с источником построчно.
* Забыли `old` для пункта `menu:` (текст пункта — тоже переводимая строка, бакет `choises`).
* Забыли `old/new` для `title_text` в `call overlay_screen(...)` (бакет `overlays`).
* Забыли имя нового говорящего в `tl/*/characters.rpy`.
