# sprite_id_map — карта id спрайтов PS2 → имя в ремастере

Дата: 2026-10-03. Файл: `references/sprite_id_map.csv`.

## 1. Что сделано

- Было: **32** строки (chapter_03, сцены 68–75).
- Добавлено: **79** строк по эталону-главе 1 (`chapter_02`) → итого **111 строк**.
- Покрытие главы 1: **102/102** различных `[SPRITE … image=+K]` размечено.
- Из них **92** имеют точный спрайт в проекте (пиксельный MAE < 15); **10** — PS2-позы,
  которых в ремастере нет собственного ассета (9 «поз B» + `mage`).

## 2. Метод

Записи спрайтов `SCENEDAT.BIN` лежат блоками по 11:

```text
B = id − ((id − 5) mod 11)          # база блока
поза A: B, B+2, B+4, B+6, B+8
поза B: B+1, B+3, B+5, B+7, B+9
выражение по позиции (id − B):
  0/1 = база, 2/3 = happy, 4/5 = angry, 6/7 = sad, 8/9 = shy
```

- **Имя позы** — пиксельная сверка `SCENEDAT.BIN[id]` ↔ `game/images/chara/**`
  (bbox-crop, RGB MAE, 128×160).
- **Поза B носит то же имя ремастера, что поза A того же блока**: ремастер схлопывает
  две разные PS2-позы в один спрайт (порт главы 1 подтверждает это девять раз).

## 4. Особые случаи

- **1105 → `mage`** (а не `npc 3`): блок 1105 смешан — id 1105 = `mage`, id 1111 =
  `npc 3` (MAE 0.72). Правило блока здесь не применяется; имя взято из скрипта
  (источник `chapter_02` стр. 338 «魔導士：ここにいたか» ↔ `mage "So there you are."`).
- 9 «поз B» (`303, 307, 336, 391, 490, 494, 556, 677, 853`): у соответствующих PS2-спрайтов
  нет собственного ассета в ремастере; порт показывает спрайт позы A того же блока.

## 5. Границы

- `uses`/`first_scene`/`first_line` новых строк — по `chapter_02` (в `notes` метка `ch1`);
  существующие 32 строки не тронуты (у них сцены 68–75).
- Колонка `layers` — слот-позиция (`layN`), а не персонаж: один слот в разных главах
  занимают разные персонажи.
- Метод не зависит от главы: глобально точный спрайт (MAE < 5) имеют ~**176/283** id (62%);
  расширение на остальные главы возможно тем же правилом.
