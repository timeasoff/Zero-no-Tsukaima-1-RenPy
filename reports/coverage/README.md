## 1. Методика

Три независимых слоя:

1. **Стандартный `tools/omission_precheck.py`** — сопоставление JA `[voice N]` с EN-голосами через `voice_id_map.csv`. Запущен по цели `22, 23, 24, 25, 26, 27, 28, extra` → везде 0 кандидатов.
   Ограничение: если в EN-скрипте нет маркеров `# ==== SCENE N ====`, охват выводится по voice-id уже портированных реплик; пропущенная сцена **не может** быть обнаружена этим инструментом (обнаружено на практике — см. §3.1).
2. **Собственный аудитор `tools/audit_coverage.py`** (создан в этом проходе) — проверяет:
   - **A** — мультимножество voice-id: источник vs порт (через манифест), ловит и пропуски, и неверные соответствия id;
   - **B** — покрытие сцен: каждый `SCENE N` источника имеет лейбл;
   - **C** — безголосые реплики: каждая JA-строка присутствует в `tl/japanese`;
   - **D** — количество `【選択肢】` vs `menu`-вариантов, `→ next`/`like`/`control`;
   - **E** — количество событий BG/CG/SPRITE/BGM/SE/VIBRATE/LAYER/TRANS/COFFEE (комментарии-эхо в `.rpy`);
   - **F** — структурная полнота TL: каждая EN-стрена имеет `old/new` в обоих языках, нет пустых `new`, дублей `old`, неверных заголовков.
3. **Ручная сверка `events_full/` и `scripts/SCENE_*.txt`** для найденных расхождений.

Evidence-таблицы: `reports/coverage/ch22_5.md`, `ch23.md` … `ch28.md`, `ch90.md`, `ch91.md`.
