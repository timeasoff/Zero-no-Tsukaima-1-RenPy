## 3. Достигаемость шкалы `zero_tundele` к `date()`

`events_full:2679`) достижимы **18 значений**, `min = 0`, `max = 255`.
Метод A (DFS+мемо) и метод B (топологический DP по DAG) дают одно множество

**Тезис 3.2 (пороги достижимы).**

* `>= 211` достижимо: `{217, 225, 247, 255}`;
* обычное дат-меню `40..210`: 10 значений.

**Тезис 3.3 (минимум решений).**

* `< 40`: минимум **4 негативных** `tndl(-30)` при **0 позитивных** → значение 7

### 3.3а. Почему «минимум 4», а не 3 (расхождение `127 + 30×3 = 217 >= 211`)

**Тезис 3.3а (структурное объяснение, поправка п.2).** Число 4 — не арифметика
порога, а **структура решений главы**. Проверка `s5_followup.py` (вывод
`s5_followup.out.txt`, раздел «структура решений»):

* На **каждом** пути до `date()` лежат ровно 10 выборов меню:
  `[6, 11, 16, 20, 29, 34, 40, 44, 54, 57]` (проверка `to×frm`: 15552 / 15552 путей
  через каждое из них); вместе с двумя map-решениями (сцены 24, 49) это и есть
  «12 решений» тезиса 3.5.
* Из этих 10 девять имеют `tndl`-опции; **ровно четыре из них не имеют нейтральной
  (нулевой) опции** — любая их опция подписана `±30`:

  | решение | опции (`events_full`) | знаки |

  | 16 | 17 (+30, `:575`) \| 18 (−30, `:576`) | `+ / −` |
  | 34 | 35 (−30, `:1366`), 36 (−30, `:1367`), 37 (−30, `:1368`) \| 38 (+30, `:1369`) | `− / − / − / +` |

  Решения 6, 11, 20, 29, 44 имеют нейтральные (нулевые) опции — сцены 9
  (`:141`), 14 (`:346`), 22 (`:780`), 30 (`:1130`), 46/47 (`:2014-2015`);
  решение 57 — обе опции нулевые (`:2535-2536`).

* Отсюда инвариант: на любом пути `npos + nneg >= 4`, и значение 4 достижимо.
  Следствия (проверены перебором всех **44** достижимых пар `(npos, nneg)`):

  * **(3 позитивных, 0 негативных) недостижима** — именно «127 + 30×3 = 217»:

* Варианты меню **равновероятны**: через каждую опцию проходит `15552 / число опций`
  путей (например, решение 34: по 3888 на каждую из 4 опций) → доли путей читаются

## 4. Какая сцена сработает при срабатывании

**Тезис 4.1.** `choice() = array[random(array.len())]`
(`SCENE_0003:2480-2482`) — равновероятный выбор.

**Тезис 4.2.** Формула id события:
`(tun ? tnEventId : dlEventId) + 2 + no*3 + event[no]`
(`SCENE_0003:2525`).

**Тезис 4.3 (слот 0, уровень 0 → id 1699 = `sp_l1`).** При первом срабатывании
`zero_tun_event/dele_event[no] = 0` (стартовый массив `[0,0,0,0,0,0]`,
`SCENE_0003:49-50`) → уровень 0 → слот 0 → id `base + 2` = **1699**
(`base = dlEventId = 1697`, тезис 2.6). Вероятность первого показа —
**1/6** (6 слотов, все в `level1` по одному разу, `:2503-2506`).

**Тезис 4.3а (повторные даты — точная формула, поправка п.3).** Поведение счётчика
по коду `getTunDeleScene` (`SCENE_0003:2485-2528`) и `dateDone` (`:2587-2599`):

* инкремент ровно показанного слота: `zero_tun_event[no]++` при флаге 1 (`:2593`),
  `zero_dele_event[no]++` при флаге 2 (`:2595`); инкремент происходит в `dateDone`,
  то есть **после** показа;
* `switch (event[i])` (`:2503-2519`, **без `default`**):

  | `event[i]` | куда попадает слот | следствие |
  |---|---|---|
  | `0` | `level1` один раз (`:2504-2506`) | вес 1 |
  | `1` | `level1` **×4** («確率４倍», `:2507-2513`) | вес 4 |
  | `2` | `level2` (`:2514-2518`) | приоритет: `choice(level2.len()>0 ? level2 : level1)` (`:2523-2524`) |
  | `> 2` | **никуда** — ветки нет | слот выпадает навсегда |

* **Формула:** если `level2` не пуст → выбор только из `level2` →
  `P(1699) = 0` (для `no = 0` id становится `1697 + 2 + 0 + 2 = 1701`);
  если `level2` пуст → `P(слот i) = вес(i) / W`, где
  `W = 4·#{слоты с event=1} + 1·#{слоты с event=0}`. Первый показ: все `event=0` →
  `W = 6` → **1/6**.
* **`1699` показывается максимум один раз**: после показа `event[0] = 1` → id
  `1699 + 1 = 1700` (тот же слот, уровень 1, вероятность выбора слота при `W = 9` —
  `4/9`; это уже **не** кормёжка 1699). Уровень 2 слота 0 → `1701`; после него
  `event[0] = 3` → слот выпадает. То есть на слот максимум **3 показа**
  (6 слотов × 3 уровня = **18 входных сцен** на блок: `1535..1552` у тун и
  `1699..1716` у дэре).
* Совокупная вероятность показа именно 1699 за `N` повторных дат при неизменных
  остальных слотах — `1 − (5/6)^N` (пока ни один слот не поднялся до 2); при
  показанном другом слоте (`event=1`) `W` растёт и вероятность падает
  (например, `W = 9` → `1/9`). Если хоть один слот достиг `event = 2`, выбор
  уходит в `level2` и `P(1699)` на эту дату = 0.
* В главе-источнике `chapter_02` ровно **один** вызов `date()`
  (`events_full:2679`, найдено grep-ом: единственный `date((0x01000000 +` …) →
  одна попытка: `P(1699 | >=211, restrict=false) = 1/6 ≈ 16.7 %`.

**Тезис 4.3б.** При `zero_tundele >= 211` дата целиком уходит в дэре-сцену:
`resetSelect2(scene)` (`:2471-2476`) перенаправляет **все** `dateItem` на выбранный
слот, `DateClear(true)` (`:2575`). То есть `P(показа любой дэре-сцены | >=211) = 1`
(если `getDeleScene() != 0`), а 1/6 — доля кормёжки среди дэре-сцен первого показа.

**Тезис 4.4 (счётчик, прежняя формулировка — сохранена и уточнена 4.3а).**
После показа `zero_tun_event[no]++` (`SCENE_0003:2593`, `zero_dele_event[no]++`
`:2595`): значение 1 → вес 4 («4/9» — вероятность выбора слота при `W = 9`),
значение 2 → уровень 2 (приоритет), значение 3 → **слот выпадает**
(switch без case 3) → максимум 3 показа на слот → **18 входных сцен**
(6 слотов × 3 уровня).

**Тезис 4.5.** Слоты `tun`/`dele` **раздельные** (`zero_tun_event` vs
`zero_dele_event`), `restrict = false` в главе 2 (`events_full:2679`) →
запрет `i == 0 || i == 3` для дэре (`:2497-2501`) не срабатывает, слот 0 доступен.
