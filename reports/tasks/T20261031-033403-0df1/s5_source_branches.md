## 2. События тундэре-метра — механизм (из кода движка)

Всё ниже — из `ps2_source/scripts/SCENE_0003.txt` (CP932, расшифрован `decode_scene3.py` → `SCENE_0003_decoded.txt`):

```
zero_tundele      0…255, старт 127;  tndl(null) -> 127;  tndl(add) -> +/- add (кламп)
date(done, restrict, bgm):
    if (zero_tundele < 40)   -> getTunScene()  = getTunDeleScene(true,  zero_tun_event,  restrict)
    else if (zero_tundele >= 211) -> getDeleScene() = getTunDeleScene(false, zero_dele_event, restrict)
    zero_tndl_done = done;  resetSelect2(zero_tndl_scene)  // меню свидания -> вычисленная сцена
    ::DateClear(zero_tndl_flag != 0)
getTunDeleScene(tun, event, restrict):
    for (i = 0; i < 6; i++) ... switch (event[i]) { case 0: level1; case 1: level1 x4; case 2: level2 }
    return (tun ? tnEventId : dlEventId) + 2 + (zero_tndl_no * 3) + event[zero_tndl_no];
tndlStart() -> next(zero_tndl_scene, true)   // прыжок в событие
tndlEnd()   -> next(zero_tndl_done, true)    // возврат к цели date()
dateDone()  -> zero_tun_event[zero_tndl_no]++ / zero_dele_event[...]++; zero_tundele_count++
```

Практические следствия для порта глав 18…29:

* `【デート進行】 → scene N` = вызов `date(N, false, +4)`: сцена `N` — это «отложенная» цель свидания; при экстремальном метре (<40 или ≥211) меню свидания заменяется событием главы 90/91, а после него `tndlEnd()` ведёт ровно в ту же `N` (пример главы 18: `date(696, …)` — событие вместо свидания, финиш всё равно в 696).
* `event[no]` может быть только 0/1/2 (в `switch` нет ветки для 3+), поэтому на слот приходится максимум 3 показа, дальше слот выпадает из пула → всего 6×3 = 18 входных сцен на блок.
* `zero_tundele_count` (число фактических изменений метра) — вход для `checkRoute()`/`checkKiss()` и для определения «пути» (см. раздел 4).
* В самих главах 18…29 `tndl` вызывается только внутри реплик-веток (`null`/±30/±40); в главах 90/91 вызовов `tndl` **нет вообще** — события метр не двигают.
